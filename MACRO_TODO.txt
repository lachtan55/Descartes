--- A4. PocketBase setup (CRITICAL for Starred Docs feature) ---

  PocketBase auto-runs all migration files in Database\pb_migrations\ at startup.
  On a new device:

  1. Copy the ENTIRE Database\ folder (including pb_data\ for existing data,
     or start fresh). Do NOT just copy pocketbase.exe alone.

  2. Start PocketBase:
       cd Database
       .\pocketbase.exe serve

  3. On FIRST RUN with a fresh pb_data\: go to http://127.0.0.1:8090/_/
     and create an admin account.

  4. On FIRST RUN, bootstrap collections (creates documents + tag_taxonomy):
       cd Database
       python ..\pocketbase_schema.py http://127.0.0.1:8090 admin@email.com YourPassword

  5. The migration 1779580800_add_starred_to_documents.js adds two fields to the
     documents collection (collection ID: pbc_3332084752):
       - starred      (bool)    — user curation flag for Highlighted Docs panel
       - starred_at   (date)    — timestamp of starring

     PocketBase runs this automatically from pb_migrations\ on every startup.
     If the collection was created BEFORE this migration existed, PocketBase will
     apply it on the next startup. Nothing manual required.

  6. frontend\.env must contain:
       VITE_POCKETBASE_URL=http://localhost:8090
     (or the production URL if deployed)

  ---- BRIDGE 1: FRED API (source = "fred_api") ----
  Affects: All US series (10 series)
  Status:  not_built → needs backend\services\fred_service.py

  API base: https://api.stlouisfed.org/fred/series/observations
  Params:   series_id=XXXX&api_key=FRED_API_KEY&file_type=json&sort_order=desc&limit=100
  Key:      FRED_API_KEY in backend\.env (free, register at fred.stlouisfed.org)

  Series to fetch:
    us_gdp_nominal_q      → FRED id: GDP           (quarterly, billions USD SAAR)
    us_gdp_nominal_a      → FRED id: GDPA          (annual)
    us_gdp_growth_q       → FRED id: A191RL1Q225SBEA  (% change annualized rate)
    us_gdp_growth_a       → FRED id: A191RL1A225NBEA  (annual % change)
    us_cpi_monthly        → FRED id: CPIAUCSL      (index 1982-84=100)
    us_core_cpi_monthly   → FRED id: CPILFESL
    us_ppi_monthly        → FRED id: PPIACO
    us_fed_funds_rate     → FRED id: FEDFUNDS      (effective rate, monthly avg)
    us_yield_2y           → FRED id: DGS2          (daily)
    us_yield_10y          → FRED id: DGS10         (daily)

  Response shape: {"observations": [{"date": "2024-01-01", "value": "123.4"}, ...]}
  Note: value comes back as a string; "." means missing (skip those points).

  Implementation skeleton for fred_service.py:

    import httpx
    from backend.config import FRED_API_KEY
    FRED_BASE = "https://api.stlouisfed.org/fred"

    async def fetch_series(series_id: str, limit: int = 40) -> list[dict]:
        url = f"{FRED_BASE}/series/observations"
        params = {
            "series_id": series_id, "api_key": FRED_API_KEY,
            "file_type": "json", "sort_order": "desc", "limit": limit,
        }
        async with httpx.AsyncClient() as client:
            r = await client.get(url, params=params)
            r.raise_for_status()
        obs = r.json()["observations"]
        return [o for o in reversed(obs) if o["value"] != "."]

  After fetching, convert to MacroDataPoint list using _dp() from macro.py.

  Series to fetch:

  ECB JSON format is complex — observations come as arrays indexed by time dimension.
  Use the ECB SDMX REST API guide: https://data-api.ecb.europa.eu/help/

  Simplest approach: use the pandas-datareader ECB reader or parse the SDMX JSON:
    pip install sdmx1    # SDMX parsing library
  Or use raw httpx + parse the "dataSets[0].series" structure.

  The Outlook table in each region dashboard currently shows hardcoded IMF/WB/OECD

  The real workflow is:
    1. User downloads WEO CSV from https://www.imf.org/en/Publications/WEO
       (April and October editions)
    2. User uploads via POST /api/macro/weo-editions (currently returns 501)
    3. Backend parses and stores by edition label (e.g., "Apr2025")
    4. GET /api/macro/outlook/{region}/{indicator} reads from stored WEO data

  WEO CSV format:
    WEO Country Code | ISO | Subject Descriptor | Subject Notes | Units | Scale |
    Country/Series-specific Estimates Start After | 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026

  Key WEO subject codes:
    NGDP_RPCH  — GDP growth (%)
    PCPIPCH    — CPI inflation (%)
    FPOLM_FFIR — Policy rate (%) [not always present]

  Storage: backend\data\weo_{edition}.json or SQLite table

  PHASE 6: DATA CACHING
  Priority: LOW (needed before production)
──────────────────────────────────────────────────────────────────────────────

  Currently all API calls to FRED/ECB/etc. happen on every request — no caching.
  MACRO_DATA_CACHE_TTL_HOURS is read from .env (default 24) but not yet used.

  Options (simplest first):
    A) In-memory dict cache with datetime TTL (zero deps, lost on restart)
    B) JSON file cache in backend\cache\ (persists across restarts)
    C) SQLite via aiosqlite or peewee (already installed)
    D) Redis (heavy — probably overkill)

  Recommended: Option B for now.
    - On request: check if backend\cache\{series_id}.json exists and is < TTL hours old
    - If yes: return cached data
    - If no: fetch from live API, write to cache, return

  Location: add caching decorator/wrapper to each *_service.py

================================================================================
  D. DATA CONTRACT — BACKEND ↔ FRONTEND
================================================================================

  Keep backend\models\macro_models.py and frontend\src\pages\macro\types.ts in sync.
  If you change one, change the other.

  MacroDataPoint:
    date: str          # ISO date "2024-01-01"
    value: float
    label?: str        # auto-generated chart X-axis label e.g. "Q1'24", "Jan'24"

  GDPData:             { region, nominal: MacroDataPoint[], growth: MacroDataPoint[] }
  CPIData:             { region, cpi: MacroDataPoint[], core_cpi: MacroDataPoint[] }
  RatesData:           { region, policy_rate: MacroDataPoint[], yield_2y?, yield_10y? }

  ForecastEntry:
    provider_id: str        # "imf", "world_bank", "oecd", "fed", "ecb", "cnb", etc.
    provider_label: str     # "IMF Apr 2025 WEO"
    color: str              # hex color e.g. "#4285F4"
    is_locked: bool         # locked providers cannot be deleted
    values: dict[str, float?]  # year_str → value e.g. {"2025": 2.3, "2026": null}
    vintage?: str

  OutlookTable:
    region, indicator, years: str[], entries: ForecastEntry[],
    consensus: dict[str, float?], high: dict[str, float?], low: dict[str, float?]

  BridgeStatus:
    source_name: str        # "fred_api", "ecb_api", "czso_api", etc.
    status: str             # "connected" | "stale" | "manual" | "not_built"
    series_count: int
    last_refreshed?: str
    last_error?: str

  MacroReport:             { model, region, content, generated_at, error? }

================================================================================
  E. GOTCHAS AND IMPORTANT NOTES
================================================================================

  1. VENV PATH
     Always use .\venv\Scripts\python.exe -m pip install (not pip.exe directly).
     On this machine there is/was a Descartes-main\ sibling folder with its own
     venv — make sure you're in Descartes-mainV2\ and using its venv.

  2. macro_catalog.json IS AUTO-CREATED
     If backend\macro_catalog.json doesn't exist on a new device, the catalog
     service creates it from the hardcoded _DEFAULT_CATALOG on the first API call.
     You do NOT need to copy or create this file manually. Any manual edits
     (toggle active, notes) made by the user ARE persisted to this JSON file —
     copy it over if you want to preserve those edits.

  3. FRONTEND TYPES MUST MATCH BACKEND MODELS
     If you add a field to a Pydantic model in macro_models.py, add it to
     types.ts as well. The frontend uses TypeScript strict mode — mismatches
     will cause build errors.

  4. CHART LABEL GENERATION
     The _dp() function in macro.py auto-generates quarter labels (Q1'24 etc.)
     from the date string. When bridging live data, make sure dates are stored
     as ISO strings "YYYY-MM-DD" and passed through _dp(). The label is used
     as the Recharts X-axis dataKey, so every point must have it.

  5. CHINA DATA QUALITY
     China series have china_disclaimer=True in the catalog. The frontend shows
     a permanent amber banner for the China dashboard. This is by design.
     Do not remove the disclaimer even when live data is connected.

  6. LOCKED FORECAST PROVIDERS
     These provider IDs cannot be deleted:
     imf, world_bank, oecd, ecb, fed, boj, pboc, cnb, bundesbank
     The 403 guard is in DELETE /api/macro/outlook/custom-provider/{id}.
     These are defined as a set _LOCKED in macro.py.

  7. AI REPORT MODELS
     The Anthropic client in macro_ai_service.py is synchronous (not async).
     It is wrapped in an async method but the client.messages.create() call
     is blocking. For production, switch to AsyncAnthropic client.

  8. POCKETBASE STARRED FIELD
     The starred and starred_at fields were added in migration
     1779580800_add_starred_to_documents.js. If PocketBase is already running
     with an old pb_data\ that predates this migration file, PocketBase will
     apply the migration automatically on next startup.

     If the migration somehow fails or the collection ID changed, the
     fetchStarredDocuments() function in pocketbase.ts has a try/catch that
     silently returns an empty list. The Highlighted Docs panel will be empty
     rather than crashing.

  9. ECB SDMX API
     The ECB API uses SDMX 2.1 format. The JSON responses are deeply nested.
     Use the sdmx1 Python library (pip install sdmx1) or parse manually:
       data = r.json()["dataSets"][0]["series"]
       # series keys are positional indices into the "structure.dimensions.series" array

  10. CORS
      CORS_ORIGINS in backend\config.py is set to localhost:5173 only.
      If deploying to production, add the production frontend URL here.

  11. RECHARTS VERSIONS
      Frontend uses recharts@2.10.3. Do NOT upgrade — there are breaking API
      changes in recharts v3. Stay on 2.x.

  12. HOW TO ADD A NEW REGION
      a) Add series to _DEFAULT_CATALOG in macro_catalog_service.py
      b) Add mock data to _get_mock_gdp(), _get_mock_cpi(), _get_mock_rates()
         and _get_mock_outlook() in macro.py
      c) Add region to LOCKED dict in _get_mock_outlook()
      d) Add region flag tab to ByRegionTab.tsx
      e) Add region to MACRO_ELIGIBLE_REGIONS in tag_mapping_service.py
